## 3. 실행 방법

`server` 폴더에서 `python -m uvicorn app:app --port 8000` → http://localhost:8000 (설치는 [server/README.md](server/README.md))

`dist/index.html`을 파일로 직접 열면 서버가 없어서 게스트 화면만 열리고, 판정과 로그인은 "서버에 연결할 수 없어요" 안내가 나옵니다.

## 4. 지표와 등급

| id | 표시명 | 단계 | 라벨 (등급 값 0, 1, 2) |
|---|---|---|---|
| `dandruff` | 각질 | 3단계 | 정상 / 경증 / 중증 |
| `sebum` | 피지 | **2단계** | 없음 / 있음 |
| `hairloss` | 탈모 | 3단계 | 정상 / 경증 / 중증 |
| `erythema` | 모낭사이홍반 | 3단계 | 정상 / 경증 / 중증 |

- 배열 순서는 **각질 → 피지 → 탈모 → 모낭사이홍반**입니다. (기존 모델 순서와 동일, 이름만 바뀜)
- 3단계 지표의 `경증`은 실제로 "경증~중등도" 범위입니다.
- **감지 = 등급 1 이상.** `render()`가 시작할 때 `syncGrades()`가 `METRICS[].grade`를 채웁니다. 우선순위는 어드민 직접 지정 > 방금 분석한 결과 > 회원의 최근 기록이고, 셋 다 없으면 "분석 결과 없음" 상태(`activeGrades()`가 `null`)입니다.
- `METRICS`의 `levels`/`labels`를 읽어 리포트 카드(피지는 2칸 게이지), 기록 표, 그래프 툴팁·범례가 지표별로 다르게 표시됩니다.
- 등급 범위 검사는 서버가 합니다(피지 0~1, 나머지 0~2).

## 5. 화면(UI) 구조

### 5.1 공통 레이아웃 (`index.html`)

- **사이드바(고정):** 로고, 메뉴(두피 분석 / 분석 리포트 / 관리 기록 / 맞춤 관리), 서비스 소개 링크. 높이가 모자라면 스크롤됩니다.
- **상단바:** 아바타, 이름(게스트는 "게스트"), 로그인·회원가입 또는 로그아웃.
- **어드민 패널:** 어드민에게만 상단바 아래에 보입니다. 보기(게스트/회원), 성별(여성/남성), 결과 지정(지표별 등급 선택, `지정 해제`).
- **푸터:** 의료 진단이 아닌 참고용이라는 안내 한 줄.
- **`main`:** 화면별 HTML 문자열이 통째로 들어가는 영역.
- **토스트:** 3.5초 뒤 사라지는 알림. 저장 실패 안내도 여기로 나옵니다.

### 5.2 화면과 주소

| 해시 | 화면 | 함수 |
|---|---|---|
| `#analysis` (기본) | 두피 분석 | `analysis()` |
| `#report` | 분석 리포트: **지금 분석한 1회 결과만** (게스트·회원 동일) | `report()` |
| `#history` | 관리 기록: **회원 전용** 누적 기록 (게스트는 로그인·가입 안내만) | `historyPage()`, `historyLocked()` |
| `#care` | 맞춤 관리: 감지 증상 요약, 증상 목록, 통합 루틴·미션 진입 | `careHome()` |
| `#care-dandruff` `#care-sebum` `#care-hairloss` `#care-erythema` (뒤에 `/ingredient` `/routine` `/product` 로 탭 지정 가능, 탭을 누르면 주소도 함께 바뀜) | 증상 상세 (성분 / 루틴 / 제품 탭) | `careDetail(id)` |
| `#care-combined` | 통합 루틴 (감지 2개 이상일 때 진입 버튼 노출) | `careCombined()` |
| `#mission` | 옛 주소. 별도 화면은 없고 `#history`로 연결됩니다 | `route()` |
| `#about` | 서비스 소개 | `about()` |
| `#login` `#signup` | 로그인, 회원가입 (로그인 상태면 `#analysis`로 이동) | `loginPage()`, `signupPage()` |

정의되지 않은 해시는 `#analysis`로 처리됩니다. `#care-*` 화면에서는 사이드바 "맞춤 관리"가 active입니다.

### 5.2-1 리포트 `#report` (지금 분석한 결과)

- 분석을 하지 않았거나 사진을 바꾼 뒤에는 "아직 분석한 결과가 없어요" 안내만 나옵니다. (`state.analyzed`)
- 위에서 아래로: 분석한 사진 → 요약 배너 → 지표 카드 4개 → 관리 바로가기 → 안내 카드 → 면책 문구.
- 어드민이 결과를 지정하면 분석 없이도 지정한 결과로 리포트가 나오고, 사진은 표시하지 않습니다.
- 그래프·인쇄·저장 버튼은 없습니다.
- **게스트:** 관리 바로가기가 감지된 증상별 `#care-<증상>/product`(제품 탭)로 이동하고, 하단에 회원가입 안내가 나옵니다. 가입·로그인해도 방금 결과는 유지되어 바로 저장할 수 있습니다.
- **회원:** 증상별 케어 상세, "관리 기록에서 루틴 체크하기" 링크, "관리 기록에서 저장하기" 버튼이 나옵니다. 저장은 자동으로 하지 않습니다.
- 분석 날짜는 항상 오늘(`today()`)입니다.

### 5.2-2 관리 기록 `#history` (회원)

위에서 아래로:

1. **저장 대기 카드:** 방금 분석한 결과가 있을 때만 표시. `기록 저장` 버튼이 여기에 있습니다. 같은 날짜의 기록이 있으면 새 결과로 **덮어씁니다**.
2. **지표 카드 4개:** 캘린더에서 고른 날짜 기준 상태. 그날 기록이 있으면 그 기록, 없으면 그 전의 가장 가까운 기록을 보여주고 위에 "10월 18일 기록" 또는 "10월 9일 기록 기준"처럼 기준일을 표시합니다. 고른 날짜 이전에 기록이 없으면 `—`로 비활성입니다. 누르면 그 지표만 그래프에 표시되고, 같은 카드를 다시 누르면 전체로 돌아갑니다. (`state.histMetric`)
3. **그래프 카드:** `주별 | 월별` 탭(기본 주별), 선택한 지표만 그리는 SVG 선 그래프, `주별(월별) 리포트 인쇄` 버튼.
   - 주별: 최근 8주(월~일), 구간 마지막 진단 결과 점. x축은 주 시작일(예: 10/19).
   - 월별: 최근 6개월, 구간 평균 점. x축은 `5월` 형식.
   - 기준 시점은 오늘이 아니라 **가장 최근 기록일**입니다. 기록이 없는 구간은 선이 끊깁니다.
   - 한 지표만 고르면 y축 라벨도 그 지표에 맞게 바뀝니다(피지는 없음/있음). 점에 마우스를 올리면 주별은 마지막 진단일·단계, 월별은 평균과 기록 수가 나옵니다.
   - 그래프는 가로 전체 폭입니다. 처음 그린 뒤 실제 폭을 재서 다시 그리고(`fitChart`, 화면 크기가 바뀌어도 반복) 좌표 1이 화면 1px이 되도록 해서 어떤 폭에서도 글자 크기가 같습니다.
4. **캘린더(3) + 루틴 미션(7):** 그래프 아래에 나란히 놓입니다(900px 이하에서는 위아래). 캘린더는 월요일 시작이고 가입일이나 첫 기록일부터 **오늘까지 모든 날짜**를 고를 수 있으며, 고른 날짜가 속한 주(월~일)에 밑줄이 그어집니다. 분석 기록(측정)이 있는 날은 칸에 검정 테두리, 루틴을 하나라도 체크한 날은 숫자 아래 점(●)이고 둘 다 한 날은 테두리 칸 안에 점이 있습니다. 오늘은 연한 회색 바탕이고, 선택일은 검정 칸입니다. 범례는 두지 않습니다. 고른 날짜를 바꾸면 지표 카드, 기록 표, 루틴 패널이 함께 바뀝니다(그래프는 기간 추이라 그대로).
5. **선택일 기록 표:** 고른 날짜의 분석 기록. `내 저장 기록 삭제` 버튼도 여기에 있습니다.

인쇄는 현재 선택한 기간(주별 또는 월별) 기준입니다. 인쇄 화면에는 제목, 그래프, 구간별 결과 표(주별 마지막 진단, 월별 평균)(`.print-only`)만 나오고 지표 카드·캘린더·기록 표 등 `.no-print` 영역은 숨깁니다.

게스트는 로그인·회원가입 안내만 봅니다. 기록이 없는 회원은 그래프 자리에 "아직 저장한 기록이 없어요"와 두피 분석 버튼이 나오고, 지표 카드는 비활성입니다. 캘린더와 루틴은 그대로 쓸 수 있습니다.

### 5.3 맞춤 관리 `#care`

- 감지된 증상 칩(이름 + 등급), 증상별 케어 행(`성분 · 루틴 · 제품 ›`), 통합 루틴 링크(2개 이상), 미션 안내.
- 모낭사이홍반이 감지되면 상단에 경고 배너가 뜹니다.
- 감지 0개면 "관리가 필요한 증상이 감지되지 않았어요"와 공통 생활 습관만 보여줍니다.
- 분석 결과가 아예 없으면 "아직 분석 결과가 없어요"와 함께 4개 증상 전체를 둘러볼 수 있게 보여줍니다.
- 하단 CTA: 게스트는 회원가입, 회원은 "관리 기록에서 루틴 체크하기".

### 5.4 증상 상세 (탭)

탭 상태는 `state.careTab`/`state.careFilter`이고, 증상이 바뀌면 `성분` 탭으로 초기화됩니다.

| 탭 | 내용 |
|---|---|
| 성분 | 추천 성분(tier 1) 카드: 전성분명, INCI, 작용, 주의, 출처. `conflictWith`에 감지 증상이 있으면 주의 표시. 홍반이면 "피하면 좋은 것". tier 2·3은 접힌 "병원·약국에서 상담하는 방법도 있어요" 안에 `약사 상담 후 구매` / `의사 진료 필요` 뱃지와 함께 설명만 표시 |
| 루틴 | 아침 / 저녁(샴푸할 때) / 주 1~2회 / 생활 습관 + 출처, 팁 박스. `softenIf` 항목은 조정된 문구(`조정됨` 표시)로 대체 |
| 제품 | 성분 필터 칩 + 제품 카드(이미지, 이름, 브랜드, 성분·`기능성`·`향료 포함`·`알코올 포함` 태그, 이유, `올리브영에서 보기`). 필터 칩은 그 증상 제품에 실제로 들어 있는 추천 성분만 나오고, 1개뿐이면 줄을 숨깁니다. 홍반 탭에서는 향료·알코올 태그가 amber색이고 카드 아래에 "민감한 두피는 팔 안쪽에 먼저 써 보세요"가 붙습니다. `url`이 없으면 "링크 준비 중" 비활성 버튼, 이미지 실패 시 아이콘으로 대체. 가격·용량은 표시하지 않음 |

제품 데이터는 2026-11-02 올리브영 상품정보 제공고시 전성분 조사 결과입니다(원본: 프로젝트 루트의 `monitoring-product-research.md`). 증상별 개수는 각질 5, 피지 5, 탈모 5, 홍반 2이고, 홍반에는 살리실릭애씨드 계열이 있는 "프로페셔널 오일컨트롤 샴푸"를 뺐습니다. `functional`/`fragrance`/`alcohol`은 조사 비고에 적힌 경우만 `true`이고 미언급은 `false`입니다. 이미지는 올리브영 서버 주소(`https://image.oliveyoung.co.kr/...`)를 직접 불러옵니다. 오프라인이거나 막히면 아이콘으로 대체되고, 로컬에 저장하려면 `image`를 `assets/...` 상대경로로 바꾸면 됩니다.

의약품(tier 2·3)에는 제품 카드나 구매 링크를 절대 만들지 않습니다. 링크는 `http(s)://`만, 이미지는 `http(s)` 또는 상대경로만 허용합니다.

### 5.5 통합 루틴 `#care-combined`

감지된 증상의 루틴을 구간별로 합치고 같은 문구는 중복 제거합니다(어느 증상에서 왔는지 칩 표시). `CONFLICTS` 중 `when`이 모두 감지된 규칙은 "이렇게 조정했어요" 박스에 항목 · 조치 · 이유로 표시합니다.

루틴 아래에 "추천 제품" 섹션이 있습니다. 감지된 증상의 제품을 홍반 > 탈모 > 각질 > 피지 순으로 모으고, 같은 `url`은 한 번만 보여주며 "해당 증상 각질 · 피지"처럼 어느 증상에 해당하는지 표시합니다. 홍반이 감지되면 모든 카드의 향료·알코올 태그가 amber색이 되고 사용 전 안내가 붙습니다.

### 5.6 루틴 미션 (관리 기록 화면, 캘린더 옆)

별도 메뉴와 화면은 없습니다. 캘린더에서 고른 날짜(`state.selectedDate`, 기본 오늘)를 기준으로 `missionPanel()`이 그립니다.

- **머리글:** `11월 2일 (월) 루틴`, 연속 달성일(오늘 체크가 있으면 오늘부터, 없으면 어제부터 이어진 일수), 오늘이 아니면 `오늘로` 버튼.
- **일 루틴:** 고른 날짜의 체크리스트. 오늘 목록은 공통 2개(`c_rinse`, `c_dry`) + 증상별 최대 3개, 우선순위 홍반 > 탈모 > 각질 > 피지로 하루 최대 5개입니다. **체크할 수 있는 건 오늘뿐**이고, 지난 날짜는 체크박스가 비활성(보기 전용)입니다. 기록이 없는 날은 안내 문구가 나옵니다.
- **그 주(월~일) 요약:** 주 달성률(%), 일 루틴 완료/전체, 월~일 7칸 막대(칸마다 완료/전체). 막대를 누르면 그 날짜로 이동합니다. 미래 날짜는 비활성입니다.
- **주 루틴:** 그 주의 `once`(과제형, 체크 + 이동 링크), `count`(누적형, `−1`/`+1`, 목표에서 멈춤). **이번 주만 수정할 수 있고** 지난 주는 보기 전용입니다. 지난 주의 목록은 그 주 기록에 저장된 미션 id를 사용합니다.
- **성별:** `gender`가 있는 미션은 그 성별에만 뜹니다. 지금은 머리 묶기(`h_loose`)↔수건 말리기(`m_towel`), 고데기(`w_no_heat`)↔손끝으로 감기(`w_gentle_wash`) 두 쌍입니다(`GENDER_PAIRS`). 어드민이 성별을 바꾸면 지난 기록의 미션도 짝으로 바꿔 보여줍니다.
- 면책 문구는 패널 맨 아래에 있습니다.

### 5.7 시각 디자인 / 반응형 / 인쇄

Figma 마케팅 사이트의 디자인 시스템에서 필요한 부분만 골라 적용했습니다. 모든 값은 `styles.css`의 `:root` 토큰으로 관리합니다.

- **면 구분:** 본문 바탕은 연한 회색(`--page`), 사이드바는 검정(`--side`, 이 값만 바꾸면 사이드바 색이 바뀝니다), 상단바와 카드는 흰색입니다. 블록과 그 안의 항목(증상 행 등)은 뚜렷한 회색 테두리(`--line`)로 나누고, 블록 안 구분선은 연한 선(`--hairline`)을 씁니다. 회색 글자를 쓰지 않고 크기와 굵기로 위계를 만듭니다.
- **선택 상태는 항상 검정:** 탭, 필터 칩, 캘린더 선택일, 선택한 지표 카드 테두리. 검정 사이드바의 활성 메뉴만 반대로 흰색입니다.
- **버튼:** 글자 버튼은 알약형, 아이콘 버튼은 원형입니다. 기본은 검정, 보조는 흰색입니다.
- **컬러 블록:** 그림자 대신 파스텔 면으로 구역을 나눕니다. 라임(분석 히어로, 저장 대기 카드), 라일락(소개, 잠금 배너), 크림(안내 카드, 조정 박스, 빈 리포트), 핑크(홍반 경고), 네이비(리포트 요약).
- **글꼴:** 본문·제목은 나눔고딕이고, INCI 성분명과 가이드 번호만 시스템 모노 글꼴입니다.
- **문구:** 영문 분류 라벨, 행사·동아리 표기, 조작 안내 문구는 화면에 두지 않습니다. 동아리와 팀 정보는 서비스 소개에만 있습니다.
- **제외한 것:** figmaSans·figmaMono(독점 글꼴), 96px 구역 간격과 86px 초대형 제목(대시보드에는 과함), 마퀴 스트립, 마젠타 프로모 버튼, 스티키 노트 장식.
- **컬러 블록 색상값:** 원문에 hex 값이 없어 근사치로 정했습니다.

**증상 등급 색(`sev-0/1/2`)** 은 초록·주황·빨강 전용입니다. 리포트 지표 카드, 관리 기록 지표 카드, 기록 표 태그, 감지 증상 칩에 공통으로 씁니다.

| 등급 값 | 의미 | 색 |
|---|---|---|
| 0 | 정상, 피지 없음 | 초록 |
| 1 | 경증(중등도 포함), 피지 있음 | 주황 |
| 2 | 중증 | 빨강 |

그래프 선 색(남색·하늘·보라·마젠타)은 등급 색과 겹치지 않게 골랐고 색각 이상 구분 검증을 통과했습니다.

- 반응형 구간: 1550 / 1150 / 900 / 620px. 620px 이하에서는 사이드바가 상단 바가 되고 메뉴 5개가 아이콘 위·글자 아래로 균등 배치됩니다. 제품 카드는 3열 → 2열(≤1150) → 1열(≤620), 성분·루틴 카드는 2열 → 1열(≤900).
- 인쇄 시 사이드바·상단바·탭·필터를 숨깁니다.

## 6. 동작 구조 (`app.js`)

### 6.1 렌더링

프레임워크 없이 **"상태 변경 → `render()`로 `main.innerHTML` 전체 교체"** 방식입니다. `render()`는 해시를 `route()`로 해석하고, 사이드바 active와 상단바 모드 표시를 갱신한 뒤 화면 함수를 호출합니다.

이벤트는 `document`의 `click`/`change`/`submit` 리스너로 처리하고 `data-action`, `data-tab`, `data-filter`, `data-mcheck`, `data-wcheck`, `data-form`, `data-view-*` 등 속성으로 분기합니다. 제품 이미지 오류는 캡처 단계 `error` 리스너 하나로 처리합니다. 탭·필터·주 루틴 버튼은 재렌더링 뒤 포커스를 복원합니다.

시작할 때 `/api/auth/me`로 로그인 상태를 확인한 뒤 첫 화면을 그립니다. 서버 호출은 `api()` 하나로 모았고, 세션이 끝나 401이 오면 게스트로 돌아가 안내합니다.

### 6.2 주요 상태 (`state`)

`photos`(`{url, file}`), `working`, `reportDate`, **`analyzed`**(지금 분석한 결과가 있는지, 사진이 바뀌면 false), **`result`**(`{grades}`), **`user`**(로그인한 회원, 게스트는 `null`), **`records`**, **`missions`**(서버에서 읽은 기록), **`view`**(어드민 보기 설정 `{mode, gender, grades}`), **`range`**, **`histMetric`**, `year/month/selectedDate`, `savedId`, `fileToken`, **`careTab`**, **`careFilter`**, **`careSymptom`**.

역할 판단은 `isAdmin()`, `isMember()`(어드민의 게스트 보기는 false), `gender()`로 합니다.

### 6.3 저장

기록과 미션은 서버 API로 저장합니다(`/api/records`, `/api/missions`). 브라우저에는 어드민 보기 설정만 `sessionStorage`(`scalp-admin-view-v1`)에 남기고, 로그아웃하면 지웁니다. 날짜 기준은 모두 Asia/Seoul 오늘입니다.

### 6.4 미션 동작 세부

- 주 기준은 **월~일**입니다(그래프의 주별 구간, 캘린더 한 줄과 같음). 주 루틴은 월요일 날짜를 키로 저장합니다. 예전 방식(회원 전환일 기준 7일)으로 저장된 주 루틴 횟수는 이어지지 않습니다.
- 오늘 일 루틴 목록은 처음 열 때 저장됩니다. **아직 체크한 항목이 없으면** 열 때마다 현재 감지 결과에 맞춰 다시 만들고, 하나라도 체크하면 그날은 고정됩니다.
- 이번 주 주 루틴도 같은 방식이며(`ensureWeekly`), 횟수는 바뀔 때만 서버에 저장합니다.
- 일 루틴 체크와 주 루틴 변경은 먼저 화면에 반영하고 서버에 보냅니다. 실패하면 되돌리고 안내합니다. 저장 요청은 순서대로 보냅니다(`queued`).
- 지난 날짜의 일 루틴과 지난 주의 주 루틴은 서버에서도 수정을 거부합니다.

### 6.5 더미 데이터

화면에는 더미 데이터가 없습니다. `demo`와 `admin` 계정에만 서버가 넣습니다(`server/seed.py`, `server/seed_data/example_records.json`).

- 분석 기록 49건(2026-05-04 ~ 10-23, 주 1~2회): 상태가 좋지 않은 5월에서 시작해 10월로 갈수록 나아집니다.
- 루틴 기록: **계정을 만든 날 기준 과거 56일**(전날까지)의 일 루틴과 지난 주들의 주 루틴입니다. 달성률은 35%대에서 90%대로 오르고 빠뜨린 날도 섞여 있습니다. 날짜를 다시 맞추려면 `python seed.py --reset`을 실행합니다.

전체 지표 그래프에서 피지는 없음 = 정상 선, 있음 = 경증 선에 찍힙니다.

## 8. 현재 한계

1. **탈모·염증 모델의 전처리는 가정값입니다.** 학습 코드가 없어 입력 크기와 정규화를 추정했고, 정답 데이터로 아직 확인하지 않았습니다. 각질은 검증 사진 180장(클래스당 60장)에서 정확도 75%를 확인했습니다.
2. **자동 저장이 없습니다.** 회원도 관리 기록의 저장 대기 카드에서 직접 저장해야 합니다.
3. **저장은 같은 날짜 덮어쓰기**만 합니다. 더미 기록과 같은 날짜에 저장하면 더미 기록이 새 결과로 바뀝니다.
4. **제품 이미지는 외부 서버에 의존합니다.** 오프라인·핫링크 차단 시 아이콘으로 대체됩니다. 이미지에 기간 한정 프로모션 문구가 들어 있고 시간이 지나면 바뀔 수 있습니다. 홍반 제품 2종의 품절 여부는 조사 때 확인하지 못했습니다.
5. **성분 출처는 이름만 표시**합니다(URL 없음). `{name, url}` 객체로 넣으면 링크가 됩니다.
6. **이번 주 달성률은 0에서 시작합니다.** 더미 루틴 기록은 전날까지만 있고, 이번 주 주 루틴은 비어 있습니다.
7. **성별은 미션에만 반영합니다.** 상품·루틴 문구는 성별 구분이 없습니다(성별별 조사 자료가 없음).
8. 어드민 패널의 결과 지정은 화면에만 적용되고, 저장을 누르면 지정한 값이 어드민 기록에 저장됩니다.
9. 레벨·뱃지 화면은 만들지 않았습니다(연속 달성일만 표시).
10. 모바일 폭과 전체 흐름은 헤드리스 Chrome으로 확인했지만, 휴대폰·태블릿 실제 기기 확인은 아직 하지 않았습니다.
11. 서버 점검은 `server/check_api.py`가 있고, 화면 자동 테스트는 프로젝트에 없습니다.

## 8-1. 서버와 DB

`server/`의 FastAPI + SQLite 백엔드가 사진 판정, 회원가입·로그인, 분석 기록, 루틴 미션을 처리합니다. 실행 방법, API, 계정, 테이블 정의는 [server/README.md](server/README.md)에 있습니다. 미션 기록 테이블은 아래와 같은 구조입니다.

| 테이블 | 컬럼 | 비고 |
|---|---|---|
| `daily_mission_log` | `user_id`, `log_date`, `mission_id`, `done_at`(비어 있으면 미완료) | 그날 뜬 미션마다 1행. `(user_id, log_date, mission_id)` 유일 |
| `weekly_mission_log` | `user_id`, `week_start`(월요일), `mission_id`, `count` | 주 루틴 누적 횟수 |

그날 뜬 미션을 행으로 남겨야 지난 날의 달성률(완료 ÷ 뜬 개수)을 계산할 수 있습니다. 완료한 것만 저장하면 분모를 알 수 없습니다.

## 현재 우선 결정 — 2026-10-27

사용자는 **시연을 우선하며, 웹 도메인 대신 기기 간에 파일을 전달하는 방식**을 선택했다. 현재 작업 기준은 로컬 `scalp-ai-demo` 폴더다. 아래에 남아 있는 실제 AI·인증·서버 DB 개발 계획은 향후 계획이며, 파일 시연보다 먼저 진행할 작업을 뜻하지 않는다.

- 전달 형식: 글꼴·샘플 이미지·CSS·JavaScript를 포함한 단일 HTML과 실행 안내를 담은 ZIP.
- 생성: 프로젝트 루트에서 `python scripts/package_demo.py` 또는 `py scripts/package_demo.py`.
- 결과물: `releases/scalp-ai-offline.html`, `releases/scalp-ai-offline.zip`.
- 실행: HTML을 브라우저로 직접 열거나 ZIP을 풀고 `scalp-ai-offline/index.html`을 연다. 받는 기기에 개발 도구나 서버 설치는 필요하지 않다.
- 기록: 브라우저에 저장한 개인 시연 기록은 전달 파일에 포함되지 않는다. 파일 경로·이름 변경과 브라우저 저장 정책에 따라 기존 기록 조회나 저장이 제한될 수 있다.
- 범위: 기존 화면·3장 입력·예시 데이터 표시를 유지한다. 휴대폰·태블릿 실행은 아직 확인하지 않았다.

파일 시연에는 아래 서버가 필요하지 않다. 소스는 `dist/index.html`을 브라우저로 직접 열 수 있고, 개발 중에는 다음 방법도 사용할 수 있다.

3. 해당 폴더의 터미널에서 실행한다.

```powershell

```

`python` 명령을 쓰는 환경에서는 다음과 같다.

```bash
python -m http.server 5500 --directory dist
```

### 현재 데이터 형식

등급 배열 순서는 **각질량 → 피지량 → 모공 밀도 → 모발사이홍반**이며, 값은 **0=정상, 1=경증, 2=중증**이다. 실제 모델의 클래스 순서와 일치하는지 별도 확인해야 한다.

저장 레코드는 현재 다음 형태다.

```json
{
  "id": "demo-생성시각",
  "date": "2026-10-27",
  "grades": [1, 0, 1, 0],
  "sample": false
}
```

`sample:false`도 사용자가 저장한 **예시 결과**라는 뜻이며, 실제 AI 분석 여부를 의미하지 않는다. 실제 분석 여부를 구분할 데이터 필드는 별도로 설계해야 한다. 서버 API 경로와 요청·응답 스키마는 아직 정해지지 않았다.

## 5. 완료한 작업

- 작품명 변경과 학교·동아리·팀원·지도교수 정보 반영.
- 5개 화면과 해시 기반 메뉴 이동.
- 사진 3장 선택·해제·미리보기. JPEG/PNG/WEBP, 장당 10MB 이하 검사 및 읽을 수 없는 이미지 처리.
- 샘플 일러스트로 즉시 체험하는 동작.
- 4개 지표의 고정 예시 리포트, 안내 문구, 브라우저 인쇄.
- 날짜·예시 등급의 브라우저 저장, 중복 저장 방지, 저장 기록 삭제.
- 월 이동·날짜 선택이 가능한 캘린더와 기록 표.
- 예시 그래프의 주간·월간 표시 전환.
- 관리 안내와 체크리스트, 반응형·인쇄 스타일.

사진은 서버로 전송하거나 localStorage에 저장하지 않는다. 새로고침하면 사진 선택과 체크 상태는 초기화되고 저장한 날짜·등급만 같은 브라우저에 남는다. 다른 기기·브라우저·사이트 주소 사이에 기록이 공유되지 않는다.

이전 웹 환경의 인수인계에서는 실제 소스와 README를 읽고, 이동용 ZIP의 주요 파일 일치 여부를 확인했다. 이후 Windows 작업 폴더로 원본 파일 11개를 가져와 원본 일치, JavaScript 문법, 로컬 서버 파일 응답을 확인했다. 브라우저 자동 실행 오류로 당시 화면·클릭 검증은 완료하지 못했다. 파일 시연본은 실제 사용할 기기에서 직접 열어 기본 동작을 확인해야 한다.

## 6. 남은 문제

현재 우선 확인할 항목은 **전달 파일의 오프라인 실행, 실제 시연 기기의 화면·사진 선택·기록 저장 동작**이다. 아래 표는 이전 실제 서비스 구현 계획의 미해결 항목과 당시 우선순위를 보존한 것으로, 지금 당장 서버·AI 구현을 시작하라는 뜻은 아니다.

| 우선순위 | 문제 | 필요한 작업 |
|---|---|---|
| P0 | 실제 소스의 기준 불명확 | 사용자의 기존 VS Code 코드가 있으면 먼저 비교. 현재 데모로 덮어쓰지 않는다. |
| P0 | 입력 장수 불일치 | 현재 웹 3장과 후속 자료의 1장 중 최종 요구사항을 확정한다. |
| P0 | AI 미연동 | 모델 가중치, 구조, 입력 크기·정규화, 클래스 매핑, 추론 코드를 확보한다. |
| P0 | 모델명 불일치 | 기존 기획의 모발사이홍반 모델은 DINOv2, 후속 자료는 DINOv3. 실제 파일을 기준으로 확인한다. |
| P0 | 성능 근거 미확인 | 학습/검증 분할 및 지표별 평가 자료가 없다. Macro F1 0.85 등의 수치를 확정 성능으로 표시하지 않는다. |
| P1 | 고정 결과가 여러 곳에 분산 | 분석, 요약, 지표 카드, 저장, 관리 안내를 하나의 실제 분석 결과 상태에 연결한다. |
| P1 | 그래프가 실제 저장 기록과 불일치 | 저장한 기록과 날짜 범위로 그래프를 계산한다. 현재 지표별 선택 기능도 없다. |
| P1 | 회원·서버 저장 없음 | 회원/게스트 정책, 인증, 기록 접근 권한, DB 저장을 구현한다. |
| P1 | 개인화 추천 없음 | 결과별 관리·상품 추천 기준과 근거 자료를 준비한다. |
| P1 | 실제 통신·추론 실패 처리 없음 | 로딩, 재시도, 시간 초과, 중복 요청, 모델 미설치·추론 실패 상태를 처리한다. |
| P2 | 개발 환경·테스트 정리 필요 | 실제 백엔드 추가 시 의존성, 설정 예시, 실행 문서, 핵심 로직 테스트를 함께 정리한다. |

기존 기획의 모델 구성은 각질량 DINOv3(B), 피지량 DINOv3, 모공 밀도 EfficientNet-B4, 모발사이홍반 DINOv2다. 후속 자료에서는 모발사이홍반도 DINOv3로 설명했다. 현재 웹 소스에서는 어느 모델도 로드하지 않는다.

## 7. 다음 할 일

1. **시연 기기 확인:** 실제 사용할 기기와 브라우저에서 전달 파일을 직접 연다. 모바일 실행은 별도 확인한다.
2. **파일 시연 확인:** 인터넷 연결 없이 샘플 체험 → 리포트 → 기록 저장 → 캘린더 → 관리 안내 → 인쇄 흐름을 확인한다.
3. **사진 선택 확인:** 시연 기기에 준비한 사진 3장을 선택하고, 선택 해제와 잘못된 형식·크기 안내를 확인한다.
4. **최종 파일 전달:** 필요한 수정은 `dist/`에 반영하고 패키징을 다시 실행한다. 실행 안내와 함께 ZIP을 전달한다. 개인 저장 기록은 함께 이동하지 않는다.

### 파일 시연 이후의 실제 서비스 개발 계획

1. **기준 프로젝트 확인:** 실제 작업할 폴더·저장소와 기존 변경사항을 확인한다. 별도 구현이 없다면 전달한 정적 웹을 시작점으로 사용한다.
2. **현재 동작 실행:** 샘플 체험 → 리포트 → 기록 저장 → 캘린더 → 관리 안내를 확인한다. 기존 디자인을 유지한다.
3. **입력·결과 계약 확정:** 사진 1장/3장, 4개 지표의 클래스 순서, 전처리, 3장일 경우 종합 규칙을 결정한다.
4. **분석 결과 상태 분리:** 예시 데이터 공급과 실제 분석 호출을 분리하고, 리포트·저장·추천이 같은 결과 상태를 참조하게 정리한다.
5. **실제 분석 한 흐름 구현:** 이미지 수신 → 전처리 → 모델 추론 → 결과 반환 → 리포트 표시를 먼저 완성한다. 실패를 예시 성공 결과로 대체하지 않는다.
6. **저장·조회 구현:** 회원/게스트 정책과 DB를 연결한 뒤 그래프·표·캘린더가 같은 기록을 사용하도록 수정한다.
7. **추천 연결 및 검증:** 결과별 안내를 연결하고 실제 사용자 흐름, 모바일 화면, 오류 상태를 검증한다.

모델 파일이 아직 없으면 분석 호출 구조와 명시적인 데모 모드까지 준비할 수 있다. 실제 모델을 검증하지 않은 상태에서 AI 구현 완료라고 표시하지 않는다. 이 하위 절의 순서는 후속 개발 계획이며 현재 파일 시연 작업에서 새로 개발한 내용은 아니다.

### 변경 후 확인 기준

- 사진 선택·삭제와 형식·크기·읽기 오류 처리가 동작한다.
- API 결과의 지표·등급이 리포트와 저장 데이터에서 일치한다.
- 실패·시간 초과·중복 요청을 처리하고 로딩 상태가 정상 종료된다.
- 그래프·표·캘린더가 동일한 데이터와 실제 날짜 범위를 사용한다.
- 실제 기록과 예시 기록을 구분한다.
- 회원 기능을 추가하면 다른 계정의 기록에 접근할 수 없도록 검증한다.
- 테스트는 클래스 매핑, 채택한 종합 규칙, 실패 응답, 기록 권한처럼 오류 영향이 큰 부분부터 작성한다.

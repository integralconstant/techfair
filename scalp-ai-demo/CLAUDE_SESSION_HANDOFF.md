# Claude 인수인계: 2026-11-04 대화에서 변경한 부분만 적용

## 적용 원칙

이 문서는 해당 대화에서 구현한 변경만 가져오기 위한 범위 명세다. 저장소 전체를 대상 프로젝트에 덮어쓰지 말고 아래 함수·스타일·API를 대상 구조에 맞춰 이식한다. 특히 `dist/app.js`, `server/app.py`, `server/routes_auth.py` 전체 교체는 피한다.

대화 시작 시점부터 작업 트리에 미커밋 변경과 미추적 파일이 있었다. 따라서 Git의 전체 diff나 이번에 푸시된 커밋 전체가 이 대화의 변경 범위와 같지 않다. 대화 시작 시점의 별도 커밋은 없으므로 정확한 Git diff만으로 범위를 자동 분리할 수 없다. 아래 명세와 코드 심볼을 기준으로 선택 적용한다.

이 문서의 경로는 `scalp-ai-demo/` 기준이다. 이 프로젝트는 `dist/` 안의 HTML/CSS/JS를 직접 수정하며, 해당 변경을 생성하는 별도 프런트엔드 빌드 작업은 수행하지 않았다.

## 1. 지표별 변화 추이: 주별 수정, 월별 롤백 유지

대상: `dist/app.js`의 `periodBuckets`, `historyChart`, `periodTable`, `historyPage`.

최종 요구사항은 **주별은 기간 내 마지막 실제 진단 결과, 월별은 기존 기간 평균**이다. 처음에는 둘 다 마지막 진단으로 변경했지만 사용자가 월별 롤백을 요청했다. 월별을 다시 마지막 진단으로 바꾸면 안 된다.

원래 중간 값의 원인은 진단값 평균(예: 0과 1의 평균 0.5)과 전체 지표 표시 시 지표별 세로 좌표 보정(`j * 2`)이었다.

- `periodBuckets`: 최근 8주 / 최근 6개월 구간 생성은 유지한다. 각 구간에 `period`, `n`, `date`, `grades`를 담는다.
- `date`는 해당 구간의 마지막 기록 날짜. 주별 `grades`는 마지막 기록의 등급, 월별 `grades`는 구간 내 모든 기록의 등급 평균이다.
- 기존 `b.avg` 소비 지점은 `b.grades`로 바뀌었다. 필드 이름은 grades지만 월별 값은 여전히 소수일 수 있다.
- 빈 구간은 null로 두고 선을 끊는다.
- 주별 점은 기준선에 정확히 정렬한다. 월별은 롤백에 따라 기존 전체 지표 보기의 `j * 2` 세로 보정도 유지한다. 단일 지표 보기에는 보정이 없다.
- 툴팁: 주별은 단계와 마지막 진단일, 월별은 평균 소수점 한 자리와 가장 가까운 단계, 공통으로 기록 수.
- 안내 문구: 주별은 마지막 진단 결과, 월별은 월 단위 평균.
- `periodTable` 인쇄 표도 주별은 단계명, 월별은 평균 숫자와 단계명을 표시한다.
- 피지는 원래부터 없음/있음 2단계다. 다른 세 지표의 정상/경증/중증 체계와 구분한다. 전체 그래프에서는 없음=정상선, 있음=경증선이라는 기존 안내를 유지한다.

## 2. 지표 한줄평 / 전체 총평

대상: `dist/app.js`의 새 `historyComment(buckets, metricId)` 및 `historyPage` 호출부, `dist/styles.css`의 `.chart-comment`와 `.chart-comment strong`.

- 특정 지표 선택 시 해당 지표 한줄평만 표시한다.
- 전체 지표 보기에서는 낮아진 지표, 높아진 지표, 같은 수준의 지표 수를 짧게 요약한다.
- 각 지표의 현재 표시 구간 중 첫 번째와 마지막 **기록이 있는 기간**을 비교한다. 직전 기록과의 비교나 회귀분석이 아니다.
- 주별은 실제 진단 단계, 월별은 평균의 변화로 표현한다. 월별은 첫 평균과 마지막 평균을 소수점 한 자리로 표시한다.
- 비교 가능한 기간이 2개 미만이면 기록 부족 안내를 표시한다. 기록 없는 구간은 비교에서 제외한다.
- 첫 값과 마지막 값이 같으면 두 기간의 결과가 같다고 표현한다. 중간 내내 같은 상태였다고 단정하지 않는다.
- 월별 총평의 동일 판정에는 `1e-9` 허용 오차를 사용한다.
- 그래프 하단 설명 다음, 인쇄 표 전에 표시한다. `role="status"` 사용. 인쇄 시에도 표시된다.

## 3. 개인정보 안내 표가 카드 밖으로 나가던 문제

대상: `dist/styles.css`의 `.consent-table` 규칙만.

전역 `table { white-space: nowrap }`를 상속받아 개인정보 안내가 줄바꿈되지 않았다. 다른 기록 표의 스타일은 유지하고 개인정보 표에 다음 속성을 추가했다.

```css
table-layout: fixed;
white-space: normal;
overflow-wrap: anywhere;
```

기존 width/font-size/line-height, th/td 여백은 유지한다.

### 백엔드

대상: `server/routes_auth.py`의 새 요청 모델과 아래 API. 기존 가입·로그인·로그아웃·조회 API는 유지한다.

| API | 요청 | 동작 |
| --- | --- | --- |
| `PATCH /api/auth/me` | `{name, gender}` | 현재 세션 회원의 이름·성별 수정, 기존 `user_json` 형식 반환 |
| `PUT /api/auth/password` | `{current_password, new_password}` | 현재 비밀번호 검증 후 해시 변경, 기존 모든 세션 폐기, 현재 브라우저 세션 재발급, 204 |
| `DELETE /api/auth/me` | `{password, confirmation: "탈퇴"}` | 현재 비밀번호 검증 후 계정 삭제, 쿠키 제거, 204 |

- 모델: `ProfileIn`, `PasswordIn`, `DeleteAccountIn`. `field_validator` import 추가. 이름은 trim하고 공백만 있는 값은 거부한다. 성별은 female/male만 허용한다.
- 인증은 기존 `Depends(auth.current_user)` 사용. 요청에서 대상 user_id를 받지 않으며, SQL은 로그인한 회원 ID로 제한한다.
- 비밀번호 해시는 기존 `auth.hash_password` / `verify_password` 사용. 비밀번호·해시는 응답에 포함하지 않는다.
- 현재 비밀번호 오입력은 400, 기존과 같은 새 비밀번호도 400. 모델 입력 검증 오류는 기존 FastAPI 422 처리 사용.
- 탈퇴는 기본 `admin`/`demo` 아이디에 403을 반환한다. 기존 시드 로직에서 기본 계정이 재생성되는 점을 고려한 제한이다.
- DB 스키마 변경은 없다. 기존 `users` / `sessions` 구조와 외래키 `ON DELETE CASCADE`를 사용한다. 계정 삭제 시 분석·일 루틴·주 루틴·세션도 삭제된다.
- 전제: `db.connect()`의 `PRAGMA foreign_keys = ON`과 기존 외래키 정의가 유지되어야 한다.
- 다른 대상 프로젝트에서 이식할 때는 기존 인증·해시·쿠키·DB 의존성에 맞춰 연결한다. 이 대화에서 기존 `auth.py`, `db.py`, `seed.py`를 변경한 것은 아니다.
